\section{System}
\label{sec:system}

\subsection{Background}

GeoCLIP~\cite{cepeda2023geoclip} encodes an image $x$ with a CLIP ViT-L/14
vision tower $f_{\mathrm{img}}$ and GPS coordinates with a location encoder
$f_{\mathrm{loc}}$, then retrieves
\begin{equation*}
\hat{g}(x)=\arg\max_{g\in\mathcal{G}}
\langle\bar f_{\mathrm{img}}(x),\bar f_{\mathrm{loc}}(g)\rangle .
\end{equation*}
Here, $\bar{\cdot}$ denotes $L_2$ normalisation and $\mathcal{G}$ is a fixed
gallery of $10^{5}$ coordinates. GeoProbe leaves $f_{\mathrm{loc}}$ and
$\mathcal{G}$ unmodified throughout; every intervention acts upon
$f_{\mathrm{img}}$ alone, so that any change in $\hat{g}$ is attributable to
the image pathway.

\subsection{Region-Conditioned Attention Intervention}
\label{sec:intervention}

In each of the $L=24$ self-attention layers of the vision tower, attention
weights are obtained as $\mathrm{softmax}(QK^{\top}/\sqrt{d})$ over a
sequence of $257$ tokens: one \texttt{CLS} token followed by $256$ patch
tokens arranged on a $16 \times 16$ grid. To probe how a selected region influences the prediction, GeoProbe modifies how attention is distributed towards patches inside and outside that region at selected layers. A binary mask \(m \in \{0,1\}^{256}\) identifies the selected patches. At layer \(\ell\), GeoProbe adds a key-indexed bias to the attention logits before softmax,
\begin{equation}
  A^{(\ell)} = \mathrm{softmax}\!\left(
  \frac{QK^{\top}}{\sqrt{d}} + \beta^{(\ell)} \right),
  \qquad
  \beta^{(\ell)}_{j} =
  \begin{cases}
    0      & j = 0 \quad (\texttt{CLS}), \\
    a_\ell & j > 0,\; m_{j-1} = 1, \\
    b_\ell & j > 0,\; m_{j-1} = 0.
  \end{cases}
  \label{eq:bias}
\end{equation}

The bias is indexed by key and broadcast across all queries and heads,
including \texttt{CLS} as a query. For each attention row, it multiplies the
unnormalised weights by $\exp(\beta_j)$ before renormalisation: the relative
weight of an in-region key against an out-of-region key is multiplied by
$\exp(a_\ell-b_\ell)$. Intuitively, $a_\ell>0$ makes every token read more
from the region, while $a_\ell\ll0$ hides it from the rest of the image. The
control can therefore be displayed as either a
logit bias or its equivalent scale factor. Setting $a_\ell=b_\ell=0$ at all
layers is an exact no-op. The \texttt{CLS} key is kept unbiased because it
has no spatial inside/outside assignment; its normalised attention weight
can still change as patch-key weights change.
The resulting output change measures the effect of this operation on the
model's computation; it does not by itself establish that a semantic object
causes the prediction in the photographed world.

\subsection{Mapping Regions to Patches}

A region delineated on the original image cannot be transferred to the patch
grid directly, since CLIP resizes the shorter side to $224$ pixels and then
applies a centre crop. GeoProbe replicates this geometry on the region
coordinates, so that a patch is marked in-region only if it remains so after
preprocessing. A patch is selected when its footprint overlaps the transformed
region. Regions falling entirely outside the centre crop yield an empty mask.
Dataset evaluation skips such images and keeps their baseline prediction,
since Eq.~\ref{eq:bias} with an empty mask would still bias every patch key by
$b_\ell$ relative to \texttt{CLS}. Multiple regions are combined by union.

\subsection{Specifying the Region}

Manually delineated rectangles support targeted case studies but do not scale
to a complete dataset. The same intervention mechanism accepts masks from either manual selection or automatic region proposals. For dataset-scale analysis, GeoProbe uses
WeDetect-Uni~\cite{fu2026wedetect}, an open-vocabulary detector run in its
visual-only configuration, which keeps proposal generation on CPU: boxes are
scored against a bank of learned objectness prompts rather than a per-image
text query. Its text tower can be enabled
when a named concept is wanted, in the manner of Grounding
DINO~\cite{liu2024grounding}. The detector never observes ground-truth
coordinates. Proposals are computed once and
cached; downstream layer searches only change the attention intervention, so
every configuration receives identical regions.

\subsection{Implementation}

A FastAPI backend loads GeoCLIP once at startup and patches the eager
attention forward pass of all $24$ vision layers according to
Eq.~\ref{eq:bias}; a React frontend provides region selection, per-layer
control and map display. One request returns both the unmodified and the
intervened top-$k$ predictions, so the comparison presented to the user is
always between two forward passes of identical weights.
